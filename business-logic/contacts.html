Contacts

Workflows for the shared contacts pool — people that can be linked to customers, vendors, or any other entity that supports contacts. A contact carries its own methods (emails and phones), and may be linked to multiple entities, each link recording its own role and notes.

The Contacts component does not know how to resolve an entity_id to a source table — that's L3's job. Every workflow that takes an entityType validates the entity exists by routing through the owning component (Customers.getCustomerById, Vendors.getById, etc.).

Composes: Contacts, Customers, Vendors, Locations — and any future component whose entity type joins the entity_type enum.

Writes​

1. Create contact​

Triggered from any place that surfaces the shared contacts UI.

Composes: Contacts.

Steps:

  1. Contacts.createContact.

Notes:

  • This workflow alone does not link the new contact to any entity. The Link workflow (§7) handles that, or callers use the Find-or-create workflow (§10) which combines both.

2. Update contact​

Triggered from a contact edit modal.

Composes: Contacts.

Steps:

  1. Contacts.getContactById — confirm.
  2. Contacts.updateContact.

Errors: NotFoundError.

3. Delete contact​

Triggered from a contact edit modal.

Composes: Contacts.

Steps:

  1. Contacts.getContactById — confirm.
  2. Contacts.deleteContact — cascades to methods and entity links.

Business rules:

  • Deletion removes the contact from every entity it was linked to.

Errors: NotFoundError.

4. Add contact method​

Triggered from a contact detail panel.

Composes: Contacts.

Steps:

  1. Contacts.getContactById — confirm.
  2. Contacts.addMethod(contactId, { type, value, label }).

Notes:

  • Email / phone format validation lives at L4 (request shape); the workflow trusts the shape.

5. Update contact method​

Triggered from a contact detail panel.

Composes: Contacts.

Steps:

  1. Contacts.updateMethod.

Errors: NotFoundError.

6. Delete contact method​

Triggered from a contact detail panel.

Composes: Contacts.

Steps:

  1. Contacts.deleteMethod.

Errors: NotFoundError.

7. Link contact to entity​

Triggered from Customer Detail / Vendor Detail / etc. → "Add contact" with an existing contact.

Composes: Contacts, plus the owning component for the entity.

Steps:

  1. Verify the contact exists.
  2. Verify the entity exists by routing through the owning component (Customers.getCustomerById, Vendors.getById, …) based on entityType. The Contacts component will not do this — it has no entity_id foreign key.
  3. Contacts.linkToEntity({ contactId, entityType, entityId, role, notes }).

Errors: NotFoundError — contact or entity not found.

8. Update contact-entity link​

Triggered from Customer/Vendor detail.

Composes: Contacts.

Steps:

  1. Contacts.getLinkById — confirm.
  2. Contacts.updateLink(linkId, patch).

Errors: NotFoundError.

9. Unlink contact from entity​

Triggered from Customer/Vendor detail.

Composes: Contacts.

Steps:

  1. Contacts.getLinkById — confirm.
  2. Contacts.unlink(linkId).

Business rules:

  • Unlinking removes the association only; the contact itself stays in the pool and may be linked to other entities.

Errors: NotFoundError.

10. Find or create contact for entity​

Triggered from quick-add flows on Customer / Vendor pages. Looks up a contact by name and (optionally) email; creates and links it if no match is found.

Composes: Contacts, plus the owning component for the entity.

Steps:

  1. Verify the entity exists (same routing as §7).
  2. Try to match an existing contact in this org: same first + last name, plus a method whose value matches the supplied email (if any). The match is conservative — close-but-not-identical contacts are not merged automatically.
  3. If a match is found, ensure it's linked to the target entity (listEntityContactsByEntity for the entity, check for an existing link). If not yet linked, linkToEntity. Return the existing contact and link.
  4. Otherwise: createContact, optionally addMethod for the supplied email, then linkToEntity. Return the new contact and link.

Returns: { contact, link, isNew }.

Notes:

  • This workflow is the only place a contact "search" runs as part of a write path. The match heuristic is deliberately strict to avoid merging distinct people who happen to share a name.

Errors: NotFoundError — entity not found.

Reads​

11. List contacts​

Composes: Contacts.

Steps: Contacts.listContacts(filters).

12. Get contact detail​

Composes: Contacts.

Steps:

  1. Contacts.getContactById.
  2. Contacts.listMethodsForContact.

13. List methods for a contact​

Composes: Contacts.

Steps: Contacts.listMethodsForContact.

14. List contacts linked to an entity​

Triggered from Customer Detail / Vendor Detail.

Composes: Contacts.

Steps: Contacts.listContactsByEntity(entityType, entityId) — returns links hydrated with contacts and methods in a single call.
