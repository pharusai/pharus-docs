Customers

Workflows for customer master data and the three classification tables that hang off it: customer types, customer segments, and brokers. Each delete on a classification row gates on whether anything still references it; the customer-side rules are otherwise plain CRUD plus a bulk-import workflow.

Composes: Customers, Contacts, SalesOrders (for the broker in-use check).

Writes​

1. Create customer​

Triggered from the Customers page → "New customer".

Composes: Customers.

Steps:

  1. Verify referenced classification rows exist and are active: type, segment, broker (each optional).
  2. If parentId is set, verify the parent exists in this org and would not create a cycle (the parent must not be a descendant of the new customer — trivially true on create, but checked anyway).
  3. Customers.createCustomer with the header fields.

Returns: the new customer.

Business rules:

  • A customer with no type / segment / broker is allowed; they're soft classifiers.
  • Parent must exist in the same org.

Errors:

  • NotFoundError — type / segment / broker / parent not found.

2. Update customer​

Triggered from Customer Detail.

Composes: Customers.

Steps:

  1. Customers.getCustomerById — confirm.
  2. If patch changes parentId, walk up the proposed chain to ensure it doesn't loop back to this customer.
  3. If patch changes type / segment / broker, verify the new value exists.
  4. Customers.updateCustomer.

Errors:

  • NotFoundError, ValidationError — parent cycle.

3. Delete customer​

Triggered from Customer Detail.

Composes: Customers, SalesOrders.

Steps:

  1. Customers.getCustomerById — confirm.
  2. Refuse if any SO references this customer (SalesOrders.listSos({ customerId }) and check empty). Customers are part of the audit trail on every SO.
  3. Refuse if the customer is the parent of another customer (children would orphan).
  4. Customers.deleteCustomer.

Business rules:

  • Deletes are blocked for any customer with order history. UI typically routes users to archive (§4) instead.

Errors:

  • NotFoundError, InUseError.

4. Bulk-import customers​

Triggered from the Data page → Customers import.

Composes: Customers.

Steps:

  1. Parse the upload. Collect parse errors.
  2. Abort on any failure.
  3. Inside one withTransaction, for each row: run Create Customer's steps 1–3.

Errors: ValidationError.

5. Create customer type​

Composes: Customers.

Steps: verify name uniqueness, Customers.createCustomerType.

Errors: ValidationError.

6. Update customer type​

Composes: Customers.

Steps: load, check name uniqueness if changed, updateCustomerType.

Errors: NotFoundError, ValidationError.

7. Delete customer type​

Composes: Customers.

Steps:

  1. Customers.isCustomerTypeInUse — refuse if any customer uses it.
  2. Customers.deleteCustomerType.

Errors: InUseError.

8. Create customer segment​

Same shape as §5.

9. Update customer segment​

Same shape as §6.

10. Delete customer segment​

Same shape as §7, calling isCustomerSegmentInUse.

11. Create broker​

Same shape as §5, calling createBroker.

12. Update broker​

Same shape as §6, calling updateBroker.

13. Delete broker​

Composes: Customers.

Steps:

  1. Customers.isBrokerInUse — checks both customers and SOs.
  2. Customers.deleteBroker if not in use.

Errors: InUseError.

Reads​

14. List customers​

Triggered from the Customers page.

Composes: Customers.

Steps: Customers.listCustomers(filters). Optionally batch-hydrate type / segment / broker names.

15. Get customer detail​

Triggered by clicking a customer.

Composes: Customers, Contacts.

Steps:

  1. Customers.getCustomerById.
  2. Hydrate type, segment, broker.
  3. Contacts.listByEntity('customer', customerId) for the linked contacts panel.

16. List customer types​

Composes: Customers.

Steps: Customers.listCustomerTypes.

17. Check if customer type is in use​

Composes: Customers.

Steps: Customers.isCustomerTypeInUse.

18. List customer segments​

Same shape as §16.

19. Check if customer segment is in use​

Same shape as §17.

20. List brokers​

Composes: Customers.

Steps: Customers.listBrokers.

21. Check if broker is in use​

Composes: Customers.

Steps: Customers.isBrokerInUse.
